# Hatch — Known Gotchas

- New Go methods are not available in `frontend/wailsjs/go/main/App.js` until `wails dev` or `wails build` regenerates bindings. Use `window['go']['main']['App']['Method'](...)` meanwhile.
- `mergeOverride` applies non-zero fields only. `Commands: []` does not clear auto-detected commands; use `DeleteScriptMeta`.
- `Args nil` shows the args input. `[]ArgDef{}` hides it.
- `Presets` are fully replaced on each `SaveScriptMeta`.
- `buildBlock` appends exported directory vars to PATH and sorts keys for stable output.
- zshrc annotation keys for positional entries (`source:N`, `other:N`, `comment:N`) change when the file is edited.
- Service detection requires both `start` and `stop` in the first 200 lines.
- Wails GUI launches do not get an interactive shell. Scripts need the explicit `source ~/.zshrc` in the executor.
- Services use `Setpgid: true`; stop targets the service process group.
- Corrupt store JSON silently resets to empty.
- `safeId(path)` replaces `btoa(path)` to avoid non-Latin-1 path errors.
- AI keys are plaintext in `config.json`; do not log or screenshot them.
- AI suggestions are not auto-saved.
- OpenAI-compatible base URL accepts either provider base or full `/chat/completions`.
- Use `findCLI()` for tools installed into login-shell-only PATH locations.
- Alpine `<template x-if>` must wrap an element; do not put bare text directly inside it.
- Nested Alpine `x-for` can fail when a method immediately reads a reactive key just set by the same click; use inline preset handlers.
- Pico CSS must load before custom CSS through `main.js`; do not add a `style.css` link in `index.html`.
- Do not use `display: revert` in the semantic element reset.
- `aria-busy` buttons and non-button `[role="button"]` elements need explicit Hatch overrides or Pico will apply blue primary styling.
- v1.2/v1.3 bound methods are often called dynamically until bindings regenerate.
- Default prompt changes must be mirrored between the hard-coded suggestion methods and `GetDefaultPrompts()`.
- The retention ticker is tied to App context; do not start duplicate tickers elsewhere.
- Run-history directories group by `filepath.Base(scriptPath)`, so same-name scripts in different dirs share a bucket.
- Pre-scripts intentionally do not emit standalone events; they appear in the main script log.
- `saveSkillContent()` auto-resyncs to enabled skill targets after master save.
- `DeleteSkill()` is Hatch-local only; it removes the master store copy and must not remove synced target skill directories.
- `DeleteSkillEverywhere()` is the explicit destructive path for removing a skill from Hatch and all sync targets.
- Skill import uses content fingerprints for same-name skills; differing content returns UI conflicts and must not overwrite Hatch master until the user chooses a side.
- MCP env values are stored in plaintext in `config.json`, like AI keys, and the MCP UI intentionally displays config values in plaintext for local review; do not log or screenshot secrets.
- MCP AI recommendations are drafts only: they can prefill `MCPServer` editor fields and quick env rows, but must not save registry entries or sync target configs until the user clicks save/enables a target.
- MCP sync writes global config only: the compatible target uses `~/.claude.json` top-level `mcpServers`, Codex uses `~/.codex/config.toml` `[mcp_servers.*]`.
- First-time MCP sync refuses to overwrite an existing same-name target entry; rename the Hatch MCP or remove the target entry first.
- Deleting a synced MCP record removes the Hatch registry entry and its Hatch-managed global target entries; use the per-target switches first if you only want to disable one side.
- `codex mcp get` may only prove config readability, not live server connectivity; show this as `unknown` rather than success.
- `switchQuickAIProvider()` must keep provider storage and `aiForm` in sync.
- New feature markup should avoid inline styles; add named classes in `style.css`.
- Hooks sync writes a `hatchId` field into each handler in `~/.claude/settings.json` and `~/.codex/hooks.json`; this is how Hatch finds its own entries. Target CLIs tolerate the extra key. If a future CLI version rejects it, fall back to matching handlers by event+matcher+command+args instead of removing the field.
- Codex hooks go in the dedicated `~/.codex/hooks.json` (Hatch-owned, merges around hand-written handlers), never inline `config.toml` `[hooks]` — that file is reserved for the MCP block and model/effort merges.
- `SetHookEnabled` first-time enable refuses to overwrite a matching hand-written hook (event+matcher+command on a non-`hatchId` handler); re-syncing an already-enabled hook overwrites its own handler. Target-unsupported events (`Notification`, `SessionEnd`) are rejected where unsupported and greyed out in the UI.
- `SaveHook()` is registry-only; the frontend `saveHook()` re-syncs already-enabled targets afterward (same pattern as `saveMCPForm`). `SuggestHookFromDescription()` is UI-draft only and must not persist.
