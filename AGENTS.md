# Hatch — Project Reference

Hatch is a **macOS script management dashboard** built with Wails v2 (Go backend + WKWebView frontend).
Target: Apple Silicon, no App Store, no Apple Developer account.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Desktop shell | [Wails v2](https://wails.io) — embeds a Go binary + WKWebView |
| Backend | Go 1.21+ |
| Frontend | Alpine.js (reactivity) + Pico.css (base) + Vite (bundler) |
| Styling | Custom CSS variables, Anthropic-inspired warm light theme, no Tailwind |
| Config | JSON at `~/Library/Application Support/Hatch/config.json` |
| Script store | JSON at `~/Library/Application Support/Hatch/scripts.json` (runtime cache) |

Build command: `$(go env GOPATH)/bin/wails build -platform darwin/arm64`
Dev mode: `$(go env GOPATH)/bin/wails dev`
Tests: `go test ./...` (use this after `app.go` binding changes), or `go test ./internal/... -v` for internal packages only

## Core Data Model (`internal/config/config.go`)

```go
type CommandPreset struct {
    Name string  // display name, e.g. "2026年4月日报"
    Args string  // space-separated args string passed at run time
}

type ScriptMeta struct {
    Path      string          // absolute path — primary key everywhere
    Name      string          // display name
    Desc      string          // one-line description
    Type      ScriptType      // "oneshot" | "service"
    Language  string          // "shell" | "python" | "ruby" | "node" | "binary"
    Commands  []string        // service sub-commands: ["start","stop","restart",...]
    PidFile   string          // service PID file path (default: /tmp/hatch/<name>.pid)
    Args      []ArgDef        // nil = show args input; [] = explicitly no args needed
    Presets   []CommandPreset // saved named invocations with fixed args
    Tags      []string
    LastRunAt int64
    UpdatedAt int64
}

type Config struct {
    Directories      []Directory           // watched dirs + optional env export
    Exports          []ExportVar           // written to ~/.zshrc managed block
    OverrideMeta     map[string]ScriptMeta // user edits keyed by script path
    ZshrcAnnotations map[string]string     // user notes on ~/.zshrc entries, keyed by entry key
    AI               AIConfig              // OpenAI-compatible model settings
}

type AIConfig struct {
    Enabled bool   // user must enable before AI actions run
    BaseURL string // OpenAI-compatible base URL, e.g. https://api.deepseek.com/v1
    APIKey  string // stored in local config.json
    Model   string // provider model id, e.g. deepseek-chat / glm-4-plus / gpt-4o-mini
}
```

**`Args` nil vs empty slice matters:**
- `nil` (Go) → JSON `null` → show args input box by default
- `[]ArgDef{}` (Go) → JSON `[]` → explicitly hide the args input

**`CommandPreset`:** Saved as part of `OverrideMeta`. Each preset renders as a `🔖 Name` button on the script card; clicking it runs the script with `preset.Args` split on whitespace.

## Script Detection: Three-Tier Fallback (`internal/scanner/`)

Applied in this order per file; later tiers only fill fields left empty by earlier ones.

**Tier 1 — `@hatch.*` annotations** (first 50 lines, any comment style `#` `//` `--`)
```sh
# @hatch.name: My Tool
# @hatch.desc: Does something useful
# @hatch.type: service          # or: oneshot
# @hatch.commands: start, stop, restart
# @hatch.pidfile: /tmp/mytool.pid
# @hatch.tags: infra, deploy
```

**Tier 2a — Service pattern detection** (`detectServicePattern`, first 200 lines)
Scans for start + stop appearing together as case arms, quoted comparisons, or usage hints.
Patterns matched per command: `start)` `"start"` `'start'` `|start|` `|start}` `{start|`
Requires both `start` AND `stop` to be present before declaring `type=service`.

**Tier 2b — `--help` probe** (`probeHelp`, 2 s timeout)
Runs `script --help`, takes the first non-empty output line as `Desc` (truncated at 120 chars).

**Tier 3 — Defaults**
`type=oneshot`, `name=filename-without-extension`, `pidFile=/tmp/hatch/<name>.pid`

**Override layer** — `config.OverrideMeta[path]` is merged on top after every scan via `mergeOverride`.
Only non-zero fields from the override replace the auto-detected value.

## App.go — Bound Methods (Go → JS API)

| Method | Purpose |
|---|---|
| `GetConfig()` | Return full config (directories, exports, overrideMeta) |
| `ScanAll()` | Rescan all script dirs, return merged `[]ScriptMeta` |
| `GetScriptsByDir(path)` | Scan a single directory |
| `AddDirectory(path, exportName, isScriptDir)` | Add dir to config, optionally write zshrc export |
| `RemoveDirectory(path)` | Remove dir + its export |
| `UpdateDirectoryExport(dirPath, exportName)` | Set/clear export for existing dir |
| `SaveScriptMeta(meta)` | Save user edit to `OverrideMeta`, persist config |
| `DeleteScriptMeta(path)` | Remove override, restore auto-detection |
| `RunScript(id, path, args)` | Launch oneshot in goroutine; events arrive via EventsEmit |
| `ServiceAction(path, action, args)` | `action`: `start` / `stop` / `restart` |
| `GetAllServiceStatuses()` | `map[path]"running"|"stopped"` for all tracked services |
| `SaveExports(exports)` | Persist export list and rewrite ~/.zshrc block |
| `CheckZshrc()` | Return shell info + current managed block line count |
| `ParseZshrc()` | Parse ~/.zshrc → `[]zshrc.Entry` (functions, aliases, exports, etc.) |
| `SaveZshrcAnnotation(key, note)` | Persist a user note for a ~/.zshrc entry key |
| `SaveAIConfig(ai)` | Persist OpenAI-compatible AI settings in config |
| `TestAIConfig(ai)` | Send a small Chat Completions request to verify model connectivity |
| `SuggestScriptMeta(meta)` | Read a script file and ask AI for name/desc/type/commands/tags/presets suggestions |
| `SuggestZshrcAnnotation(entry)` | Ask AI for a short Chinese note for one parsed zshrc entry |

**New methods not yet in `wailsjs/App.js`** (regenerated on next `wails build`):
Call them directly in `main.js` via `window['go']['main']['App']['MethodName']()`.

### AI integration model

Current AI support targets APIs compatible with OpenAI Chat Completions (`POST /chat/completions`), including providers such as DeepSeek, GLM, and OpenAI.

- `AIConfig.BaseURL` may be either provider base URL (`https://api.deepseek.com/v1`) or the full chat completions URL; `app.go` appends `/chat/completions` if missing.
- `APIKey` is stored locally in `~/Library/Application Support/Hatch/config.json`. There is no keychain integration yet.
- AI requests are synchronous Wails calls with a 45 s HTTP timeout.
- Script analysis reads the script file, truncates content to 12,000 bytes, and asks for strict JSON.
- AI suggestions are not auto-saved. They populate the edit drawer or annotation input; the user still clicks Save.
- If AI is disabled or incomplete, frontend navigates to the AI tab and shows an error.

## Real-time Events (Go → JS via Wails EventsEmit)

| Event | Payload | When |
|---|---|---|
| `executor:log` | `{id, line, stream}` stream=`stdout`\|`stderr` | Every output line from a running script |
| `executor:done` | `{id, exitCode}` | Oneshot completed |
| `executor:status` | `{id, status}` status=`running`\|`stopped`\|`error` | Service state changes |

`id` is always the script's absolute `path`. Listened to in `main.js` via `EventsOn`.

## Service Execution Model (`internal/executor/`)

**Oneshot** (`oneshot.go`):
- Runs via `/bin/zsh -l -c` (login shell, sources zshrc, full PATH)
- `stdout` and `stderr` streamed line-by-line via `Emitter.Log`
- `Emitter.Done` fires on completion with exit code

**Service** (`service.go` — `ServiceManager`):
- Start: launches script in background with `Setpgid: true` (own process group)
- PID written to `pidFile` (default `/tmp/hatch/<name>.pid`)
- Status: `kill -0 <pid>` liveness probe; stale PID files auto-removed
- Stop: `SIGTERM` + PID file cleanup
- Restart: Stop (ignore error) → Start
- On app startup: `restoreServices()` rebuilds `ServiceManager` for all stored service scripts and probes each one

## Zshrc Management (`internal/zshrc/`)

### Managed block (`manager.go`)

Format (conda/nvm style — idempotent, never corrupts other content):
```sh
# >>> Hatch managed block >>>
export MY_TOOLS="/Users/you/tools"
export SCRIPTS="/Users/you/scripts"
# <<< Hatch managed block <<<
```

Rules:
- Block is replaced atomically on every write; lines outside are never touched
- Keys written in **alphabetical order** for stable diffs
- `RemoveBlock` called automatically when the exports list becomes empty
- `WriteBlock` appends if no block exists, or replaces via regex if it does

### Shell config parser (`parser.go`)

`ParseContent(content string, annotations map[string]string) []Entry`

Parses raw zshrc text into typed `Entry` structs. Entry types:

| Type | Detected from | Key |
|---|---|---|
| `function` | `function name {` or `name() {` (multi-line body captured) | function name |
| `alias` | `alias name=value` | alias name |
| `export` | `export VAR=value` | variable name |
| `path` | `export PATH=…` or bare `PATH=…` | `"PATH"` |
| `source` | `source file` or `. file` | `"source:N"` (line number) |
| `section` | `# comment text` | `"comment:N"` |
| `other` | everything else (nvm, conda, eval, …) | `"other:N"` |

The Hatch managed block is skipped entirely. User annotations are attached by matching `Entry.Key` against the `ZshrcAnnotations` map in config.

## Frontend Architecture (`frontend/`)

### State machine (Alpine.js `hatchApp()` in `main.js`)

```
tab = 'scripts' | 'settings' | 'ai'
selectedDir = null | { path, exportName, isScriptDir }

tab='scripts' && !selectedDir  →  Directory card list
tab='scripts' && selectedDir   →  Script list for that directory
tab='settings'                 →  Settings panel (4 sections)
tab='ai' && !selectedDir       →  OpenAI-compatible model configuration
editTarget != null             →  Edit drawer overlay (any tab)
quickExportDir != null         →  Quick export modal overlay
```

### Key state fields

| Field | Type | Purpose |
|---|---|---|
| `allScripts` | `ScriptMeta[]` | Result of `ScanAll()`, used for directory card counters |
| `currentScripts` | `ScriptMeta[]` | Result of `GetScriptsByDir()`, shown in script list |
| `statuses` | `{path: string}` | `"running"\|"stopped"`, polled every 3 s |
| `runningSet` | `{path: true}` | In-progress oneshot runs |
| `scriptLogs` | `{path: [{line,stream}]}` | Capped at 500 lines per script |
| `scriptExitCodes` | `{path: number}` | Exit code stored on `executor:done` |
| `logTarget` | `string\|null` | Which script's log panel is open |
| `editTarget` / `editForm` / `editSaving` | — | Edit drawer state |
| `aiForm` | `{enabled,baseUrl,apiKey,model}` | AI provider config shown in the AI tab |
| `aiSaving` / `aiTesting` | `bool` | AI config save/test loading states |
| `aiBusyScript` / `aiBusyEntry` | `string\|null` | Per-script/per-zshrc-entry AI loading indicators |
| `zshrcEntries` | `Entry[]` | Parsed ~/.zshrc entries |
| `zshrcFilter` | `string` | Active type filter in Shell 配置解析 |
| `annotationTarget` | `string\|null` | Key of entry being annotated |
| `expandedFns` | `{key: bool}` | Which function bodies are expanded |

### Edit drawer flow

1. Click `✏ 编辑` on any script card → `openEdit(s)` populates `editForm`
2. User edits: name / desc / tags / type / sub-commands / pidFile / needsArgs / **presets**
3. `saveEdit()` → `SaveScriptMeta()` → `scanDir()` to refresh → close drawer
4. `resetEdit()` → `DeleteScriptMeta()` → removes override, auto-detection resumes

**AI script flow:** Click `✦ 智能填写` on a script card → `SuggestScriptMeta(s)` reads the script and returns suggestions → `openEdit(s)` opens the drawer → AI results fill editable fields → user reviews and clicks `💾 保存`. It must not silently persist metadata.

**Preset flow in drawer:** "命令预设" section lists `{name, args}` pairs.
Add via `addPreset()`, remove via `removePreset(i)`. Saved into `meta.Presets`.

### Log panel behavior

- Auto-opens when a script is started (`runScript` sets `logTarget = id`)
- `x-show="logTarget === s.path"` — stays open until user closes it
- Header shows: `● 运行中` (blinking, while `runningSet[path]`) → `✓ exit 0` or `✗ exit N` on completion
- Service actions (start/stop/restart) inject `[hatch] action…` / `[hatch] action OK` log lines
- Clear button resets log and removes stored exit code

## Installation Paths

### App bundle

| Location | Path |
|---|---|
| Installed app | `/Applications/Hatch.app` |
| Go binary (embedded) | `/Applications/Hatch.app/Contents/MacOS/Hatch` |
| Web assets (embedded) | `/Applications/Hatch.app/Contents/Resources/` |
| Local dev build | `build/bin/Hatch.app` (relative to repo root) |
| DMG installer | `build/bin/Hatch-<VERSION>-arm64.dmg` |

### Runtime data directories

All user data lives outside the app bundle and survives reinstalls.

| Purpose | Path | Created by |
|---|---|---|
| User config (dirs, exports, overrides, annotations) | `~/Library/Application Support/Hatch/config.json` | `internal/config` on first `Save()` |
| Script metadata cache | `~/Library/Application Support/Hatch/scripts.json` | `internal/store` on first `Replace()` |
| Service PID files (default) | `/tmp/hatch/<script-name>.pid` | `internal/executor/service.go` on service start |
| Shell managed block | `~/.zshrc` (Hatch block only) | `internal/zshrc/manager.go` on export save |

> `os.UserConfigDir()` resolves to `~/Library/Application Support` on macOS.
> Both `config.json` and `scripts.json` are therefore in the same directory.
> If `UserConfigDir()` fails, the store falls back to `$TMPDIR/hatch/scripts.json`.
> AI API settings, including `apiKey`, are stored in `config.json`.

### Resetting / uninstalling

```bash
# Remove app
rm -rf /Applications/Hatch.app

# Remove all user data (config, script cache)
rm -rf ~/Library/Application\ Support/Hatch/

# Remove shell managed block (or just delete the lines between the markers)
# >>> Hatch managed block >>>  …  <<< Hatch managed block <<<

# Remove stale PID files
rm -rf /tmp/hatch/
```

## Known Patterns & Gotchas

- **New Go methods not in wailsjs yet**: Call them as `window['go']['main']['App']['Method']()` directly in `main.js` until the next `wails build` regenerates the bindings.
- **`mergeOverride` only applies non-zero fields** — setting `Commands: []` in an override does NOT clear auto-detected commands; use `DeleteScriptMeta` to fully reset.
- **`Presets` in override**: stored inside `OverrideMeta[path].Presets`; fully replaced on every `SaveScriptMeta` call.
- **`ZshrcAnnotations` keys**: for named entries (functions, aliases, exports) the key is the identifier itself; for positional entries (source, other, section/comment) it is `"type:lineNum"` — these keys change if the file is edited.
- **Service script detection requires both `start` AND `stop`** in the first 200 lines.
- **Login shell execution** (`/bin/zsh -l -c`) means `~/.zshrc` is sourced for every run — PATH and exports are available to scripts.
- **`Setpgid: true`** on service processes means `Stop()` sends SIGTERM to the script's own process group, not the Hatch process group.
- **Corrupt store JSON** silently resets to empty (no crash) — normal after first run.
- **Map iteration is non-deterministic** — `buildBlock` in `zshrc/manager.go` sorts keys before writing to ensure stable, diff-friendly output.
- **`safeId(path)`** replaces `btoa(path)` in the log panel DOM id — avoids `btoa` encoding errors on non-Latin-1 characters in paths.
- **AI API key is local plaintext config** — do not print it in logs or expose it in screenshots; future keychain storage would be a separate change.
- **AI suggestions require user confirmation** — script metadata and zshrc notes are filled into existing manual UI and must be saved explicitly.
- **OpenAI-compatible URL handling** — `BaseURL` accepts either provider base (`.../v1`) or full `/chat/completions`; backend appends `/chat/completions` only when missing.
- **Generated Wails bindings** — `frontend/wailsjs/` is generated. New methods can be called directly from `window['go']['main']['App']` until a Wails build regenerates files.
